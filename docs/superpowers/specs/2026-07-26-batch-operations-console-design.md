# AutoComment 批处理桌面作业控制台设计

## 背景

AutoComment 已支持：

- 在控制台所在 Chrome 窗口内用 1–10 个后台 worker 标签页并发处理目标网站；
- 批次检查点、系统保活和 Chrome 重启后的安全恢复；
- 本地评论历史、结果导出和失败原因记录；
- 一个全局身份、一个推广网站和一组批处理自动化设置。

现有 `batch.html` 仍是一张最大宽度 700px 的单列长表单。上传、设置、状态、进度和终态结果分散在不同卡片中，主要操作位于页面中下部。运行时看不到并发槽位、排队任务和逐 URL 阶段；失败、需人工确认和恢复状态也缺少就地处置入口。

`batch.js` 已增长到 2,349 行，同时承担 DOM 查询、CSV 解析、设置持久化、运行时编排、Chrome 标签页副作用、结果统计、筛选和页面渲染。继续在该文件增加界面状态会进一步放大耦合。

本设计将批处理页重构为“桌面作业控制台”，让单窗口多 worker 标签页并发真正可操作、可观察、可恢复，同时建立多身份/多推广网站就绪的界面和数据契约。

## 自动 worker 资源模型决策变更（2026-07-26）

初稿采用“每个自动 worker 一个普通 Chrome 窗口”。该决定已被后续约束覆盖：自动并发必须调用 `chrome.tabs.create({ windowId: 控制台所在窗口, url, active: false })`，以 `tabId` 作为唯一关闭和监听资源；共享 `windowId` 只表示承载窗口，不能作为 manager 的资源键，也不能由自动 runtime 关闭。

人工处理仍可打开独立普通窗口，但它不进入自动 worker runtime、不接收 `BATCH_HANDLE`、不占并发槽位，也不自动生成、填写或提交。文档后文若提到“人工窗口”，仅指这一人工路径。

## 目标

- 用统一导航表达“身份配置 → 推广网站配置 → 目标网站批次 → 评论历史”的关系。
- 将批次创建与批次运行分层，避免单列长表单。
- 在页面顶部提供始终可见的批次状态和主要控制。
- 可视化并发槽位、排队/运行/成功/失败/需人工数量和逐 URL 阶段。
- 让错误原因、重试、人工处理和恢复操作在任务行或详情区内完成。
- 明确暂停、继续和永久停止的安全语义与危险层级。
- 覆盖空状态、离线、检查点失败、Chrome 重启恢复和响应式布局。
- 将 UI、状态推导、命令编排和 Chrome 副作用拆成可独立测试的模块。
- 为身份、推广网站和批次分配建立稳定契约，但仍只使用当前单一配置。

## 非目标

- 不实现多个身份或多个推广网站的运行时调度。
- 不支持同一个 Chrome 配置文件并行运行多个独立批次。
- 不改写评论框识别、文案生成、非法站点规则或评论历史数据模型。
- 不把完整调度器迁移到 Manifest V3 service worker。
- 不引入远程图片、远程字体、远程脚本或违反扩展 CSP 的代码。
- 不在真实第三方网站上进行验收提交。

## 方案选择

### 方案 A：桌面作业控制台（采用）

主页面持续显示固定控制栏、批次指标、并发槽位和完整队列表格。新建批次使用右侧宽抽屉完成，开始后回到同一个控制台。

优点：

- 最适合长时间、单窗口多标签页的桌面作业。
- 操作、监控和处置处于同一上下文。
- 能充分利用宽屏空间。
- 后续增加身份和推广网站选择器时不需要重做信息架构。

代价：

- 需要同时重构页面结构、样式和 `batch.js` 职责边界。
- 中窄屏需要专门设计折叠方式。

### 方案 B：向导优先

使用独立多步向导创建批次，开始后切换到监控页。首次使用清晰，但创建和运行分属两套页面，频繁操作成本较高。

### 方案 C：双栏工作台

左侧始终显示配置，右侧显示队列。改动路径较短，但运行中配置区价值下降，队列、错误和行操作在中等宽度下过于拥挤。

## 信息架构与统一导航

所有扩展管理页面共享顶栏：

1. 批次；
2. 身份配置；
3. 推广网站；
4. 评论历史；
5. 设置。

当前实现继续使用已有页面：

- “批次”打开 `batch.html`；
- “身份配置”打开 `options.html#identity`；
- “推广网站”打开 `options.html#promotion`；
- “评论历史”打开 `history.html`；
- “设置”打开 `options.html#settings`。

`options.html` 仍保存一个身份和一个推广网站，只按上述区段重组现有表单。导航入口的分离用于解释概念关系，并为以后真正的多配置页面保留稳定目标。

每个页面必须：

- 用文本和视觉样式共同标识当前导航项；
- 支持键盘导航和可见焦点环；
- 显示本地运行状态，不暗示存在尚未实现的云同步；
- 在窄屏折叠为可访问的导航菜单。

## 批次控制台

### 顶部固定操作栏

固定栏位于共享导航下方，包含：

- 批次名称和状态；
- 暂停或继续；
- 永久停止；
- 导出当前结果；
- 新建批次。

操作栏固定在扩展页面视口顶部，不遮挡队列表头。状态必须以文字展示，不能只依赖颜色。

操作层级：

- “继续处理”和“新建批次”为主要操作；
- “暂停”为普通次要操作；
- “停止批次…”为危险入口，必须先展示不可恢复后果；
- “导出当前结果”始终保持非危险样式。

### 摘要指标

固定栏下方显示：

- 总目标；
- 排队；
- 运行；
- 成功/已存在；
- 失败；
- 需人工。

摘要由同一个控制台快照推导，不能分别维护独立计数，以避免恢复和重试后不一致。

### 左侧运行区

桌面宽度下左侧包含：

- 当前批次分配：身份、推广网站、自动化模式、并发数和超时；
- 并发槽位：每个自动 worker 标签页的域名、耗时、阶段和标签页标识；
- 运行保障：检查点最近保存状态、系统保活、离线或后台异常。

并发槽位数量等于当前批次固定的并发设置。空闲槽位显示“等待队列”，活动槽位显示受控阶段：

- `opening`：正在创建 worker 标签页；
- `loading`：正在加载目标页面；
- `detecting`：正在识别评论表单；
- `generating`：正在生成文案；
- `filling`：正在填写表单；
- `submitting`：正在准备或执行提交；
- `confirming`：正在等待提交确认；
- `closing`：正在安全关闭 worker 标签页。

### 目标队列表格

表格覆盖任务完整生命周期，而不是只显示终态结果。列包括：

- 原始序号；
- 完整目标 URL；
- 状态；
- 当前耗时；
- 当前阶段或错误摘要；
- worker 标签页；
- 行操作。

支持：

- 状态、域名和耗时筛选；
- URL、AI 内容和错误搜索；
- 行详情抽屉；
- 查看活动 worker 标签页；
- 安全重试；
- 人工处理；
- 复制 URL；
- 查看终态和历史保存详情。

筛选不会改变运行调度，只影响视图。

### 任务详情

详情抽屉展示：

- URL 和批次任务身份；
- 阶段时间线；
- 结构化错误码和用户消息；
- AI 内容和本地历史保存状态；
- 当前允许的操作及其风险说明；
- 人工处置记录。

错误消息使用文本换行而不是仅用截断标题属性。表格可显示摘要，详情必须保留完整内容。

## 空状态与批次创建向导

没有活动或已载入批次时，控制台显示：

- “创建第一个目标网站批次”主操作；
- 简要说明身份、推广网站和目标 CSV 的关系；
- 如果存在恢复检查点，优先显示恢复卡片而不是空创建提示。

点击“新建批次”打开右侧宽抽屉。抽屉包含四步：

1. 分配配置；
2. 导入与预检；
3. 自动化参数；
4. 确认并开始。

宽屏保留背景控制台；窄屏切换为全页向导。关闭向导不会启动窗口。草稿使用独立的 `batchDraftV1` 本地存储键；草稿永远不能被后台解释为活动批次检查点。

### 步骤 1：分配配置

当前只提供：

- `default-identity`；
- `default-promotion-site`。

选择卡显示现有姓名/邮箱和推广网站 URL/内容摘要，并提供跳转到配置页的入口。界面文案明确标注“当前为单身份运行”，不展示不可用的新增、轮换或权重调度控件。

### 步骤 2：导入与预检

导入 CSV 后显示：

- 原始行数；
- 将处理数量；
- 重复数量；
- 非法拦截数量；
- 格式错误数量。

每行输出以下状态之一：

- `eligible`：可处理；
- `duplicate`：重复，默认排除，但可显式保留；
- `blocked`：命中非法站点规则，不可强制加入；
- `invalid`：不是有效的 HTTP/HTTPS URL，不可强制加入。

每行同时包含稳定原因码、用户消息和是否允许覆盖。预检模块只处理数据，不读写 DOM。

### 步骤 3：自动化参数

集中配置：

- 自动打开推广助手；
- 自动生成；
- 自动提交；
- 并发窗口数 1–10；
- 单页超时 10–600 秒。

自动提交启用时显示风险说明。依赖关系必须在界面和校验层同时执行：自动提交要求自动生成；开始时仍复用现有模型配置就绪检查。

### 步骤 4：确认并开始

汇总：

- 身份和推广网站快照；
- 有效目标与排除数量；
- 自动化模式；
- 并发和超时；
- 风险提示。

用户点击“开始批次”后才创建持久化检查点、申请系统保活并在控制台所在窗口创建后台 worker 标签页。

## 暂停、继续与停止

### 暂停

暂停语义：

1. 立即停止调度补位；
2. 停止领取新 URL；
3. 对每个活动 worker 标签页执行提交上下文封存；
4. 加载、识别、生成和填充阶段的任务安全回到队列；
5. 已进入提交但未确认的任务转为 `manual_required`；
6. 关闭活动 worker 标签页；
7. 保存 `paused_recovery` 检查点；
8. 释放系统保活。

暂停过程中操作栏显示“正在安全暂停 X/Y”，且停止、重试和新建批次不可用。暂停完成后主要操作变为“继续处理”。

### 继续

继续前重新读取和验证最新检查点，申请系统保活，并只调度可安全继续的排队任务。已终态和需人工任务不会被自动重新领取。

### 永久停止

停止是不可恢复操作。确认对话框必须明确：

- 已有结果继续保留并可导出；
- 剩余任务不会继续；
- 原批次不能恢复；
- 如需重跑，必须复制配置创建新批次。

确认后使用红色“停止并保留结果”按钮。停止与暂停不能共用同一个模糊按钮或结果状态。

## 重试策略

重试策略由结构化结果和错误码决定：

| 结果/错误 | 策略 | 默认操作 |
| --- | --- | --- |
| 处理超时、标签页创建失败、内容脚本未就绪 | `safe` | 直接重新排队 |
| 无评论框 | `safe` | 重试或人工处理 |
| 需人工确认、提交确认前中断 | `confirm` | 先人工检查；自动重试需二次确认 |
| 成功、已存在 | `blocked` | 禁止重试 |
| 非法拦截 | `blocked` | 禁止重试并解释规则 |

安全重试把允许的终态任务转换为新的 `queued` 尝试，并清除旧 worker 标签页身份和计时信息。旧结果作为尝试历史保留，当前任务行展示最近一次尝试。

高风险重试必须说明可能造成重复评论。用户确认后才允许重新排队。

## 人工处理

点击“人工处理”时：

- 使用普通 Chrome 窗口打开目标 URL；
- 不发送 `BATCH_HANDLE`；
- 不触发自动打开助手、自动生成、自动填写或自动提交；
- 不登记为自动 worker，不占用并发槽位；
- 在任务详情中记录 `in_progress`。

关闭人工窗口不会自动猜测是否成功。用户必须选择：

- “标记已处理”；
- “仍未解决”。

任务的核心运行态仍保持 `terminal`，人工处置作为附加元数据保存：

```js
{
  status: 'idle' | 'in_progress' | 'resolved' | 'unresolved',
  updatedAt: 0
}
```

“已处理”只表示用户完成了人工检查或处置，不自动写入成功评论历史，也不计入自动成功率。

## 离线与恢复

### 离线

`navigator.onLine === false` 或浏览器离线事件触发时：

- 停止调度新任务；
- 执行与暂停相同的活动窗口安全处理；
- 保存暂停检查点；
- 显示离线横幅；
- 释放系统保活。

浏览器恢复在线只更新横幅和可用操作。任务不会自动继续，必须由用户点击“继续处理”。

### 关键运行时失败

检查点写入失败、保活申请失败或后台关键命令失败时：

- 不继续创建窗口；
- 能保存时转为 `paused_recovery`；
- 显示完整用户消息和可复制诊断码；
- 提供重试读取、导出已有结果和永久停止；
- 不隐藏或清除原始恢复数据。

### Chrome 重启或页面刷新

沿用现有中断归一化规则：

- `queued` 保持排队；
- `active` 回到排队；
- `submitting` 转为一次性 `manual_required`；
- 终态结果保持不变；
- 批次进入 `paused_recovery`；
- 用户确认后才继续。

恢复横幅明确列出重新排队数量、转人工数量和已有终态数量。

## 响应式布局

- `>= 1280px`：左侧运行区和右侧队列表格并排。
- `900–1279px`：批次分配、槽位和运行保障折叠为表格上方的概览区。
- `< 900px`：顶部操作栏允许换行，队列切换为逐任务卡片；创建抽屉变为全页。
- `< 640px`：导航折叠，摘要指标两列显示，危险操作仍保留完整文字。

任何宽度下都必须保留：

- 状态文字；
- 完整错误访问入口；
- 暂停、继续和停止的语义差异；
- 与桌面表格等价的任务信息和行操作。

## 可访问性

- 使用 `header`、`nav`、`main`、`aside`、`table`、`dialog` 等语义结构。
- 状态变化、恢复警告和关键计数使用节流后的 `aria-live` 区域。
- 抽屉和对话框打开时锁定焦点，关闭时把焦点还给触发器。
- Escape 关闭非危险详情；未确认的停止对话框可取消；开始执行中的关键过渡不能被 Escape 静默丢弃。
- 所有图标按钮必须有可见或辅助名称。
- 焦点环清晰可见，命中区至少 40×40 CSS 像素。
- 状态使用文字、形状和颜色共同表达。
- 支持 `prefers-reduced-motion`，不依赖动画表达阶段。

## Manifest V3 与 CSP

- 所有样式、脚本、SVG 和字体均来自扩展包或系统字体。
- 页面 JavaScript 继续使用本地 ES modules。
- 不使用内联事件处理、`eval`、远程模块或远程图片。
- 人工窗口使用现有 Chrome window API，不注入新远程代码。

## 架构

### 共享页面外壳

`lib/app-shell.mjs`

- 渲染统一导航；
- 解析当前页面和 `options.html` 区段；
- 暴露导航事件；
- 渲染本地运行状态；
- 不读取或修改业务数据。

共享样式拆到本地 CSS：

- `styles/tokens.css`；
- `styles/app-shell.css`；
- `styles/forms.css`；
- 页面专属样式。

### 批次视图

`lib/batch-console-view.mjs`

- 渲染控制栏、摘要、槽位、队列、详情和对话框；
- 只接收 `BatchConsoleSnapshot`；
- 使用事件委托发出语义化 UI 命令；
- 不直接调用 Chrome API。

`lib/batch-wizard-view.mjs`

- 渲染向导和预检；
- 管理焦点与步骤导航；
- 发出草稿更新、开始和取消命令；
- 不创建运行时检查点。

### 纯状态与规则

`lib/batch-console-state.mjs`

- 从检查点、窗口活动和本地 UI 状态推导控制台快照；
- 统一生成计数、槽位、队列行、横幅和允许操作；
- 不访问 DOM、storage 或 Chrome API。

`lib/batch-preflight.mjs`

- 解析并规范化 CSV 行；
- 运行重复、非法和 URL 格式检查；
- 返回稳定预检状态、原因码和覆盖策略。

`lib/batch-error-policy.mjs`

- 将结构化错误码映射为用户消息；
- 生成 `safe | confirm | blocked` 重试策略；
- 禁止 UI 通过错误字符串猜测行为。

### 命令编排

`lib/batch-command-controller.mjs`

- 编排开始、暂停、继续、停止、重试和人工处置；
- 接收注入的 runtime、window、storage 和 clock 适配器；
- 保证 UI 命令在执行中幂等禁用；
- 发生关键错误时进入安全暂停流程。

### 批次入口

`batch.js` 缩减为：

- 页面启动；
- 构造依赖；
- 加载设置和检查点；
- 连接 view、state 和 command controller；
- 订阅 runtime 消息；
- 销毁监听器。

CSV 解析、DOM 生成、错误策略和大段生命周期分支不得继续留在入口文件。

### 运行时扩展

现有 `batch-runtime-controller.mjs` 继续作为检查点唯一写入者。增加语义化命令：

- `BATCH_TASK_PHASE`；
- `BATCH_TASK_RETRY`；
- `BATCH_TASK_MANUAL_UPDATE`。

后台必须继续串行化同一批次写入并校验 `batchId + urlIndex`。

任务核心状态仍为：

- `queued`；
- `active`；
- `submitting`；
- `terminal`。

阶段和人工处置是附加数据，不增加第二套调度状态机。

`BATCH_TASK_RETRY` 仅允许符合重试策略的终态转换为 `queued`。重试生成新的尝试序号，旧 attempt 结果不丢失。

人工窗口使用独立适配器创建，不登记到自动 runtime 的 `BatchTabManager`，避免关闭人工窗口被解释为 worker 失败。

### 检查点版本与迁移

检查点从版本 1 升级为版本 2。版本 2 在每个任务中增加：

```js
{
  attempt: 1,
  phase: null,
  manualResolution: {
    status: 'idle',
    updatedAt: null
  }
}
```

结果记录增加对应的 `attempt`。安全或高风险重试会：

1. 把当前终态结果保留在结果历史；
2. 将任务 `attempt` 加一；
3. 清除当前阶段、窗口身份、开始时间和旧人工处置；
4. 将核心状态改回 `queued`。

旧 attempt 的延迟阶段或确认消息必须被拒绝。所有阶段、终态和重试命令都携带并校验 `attempt`。

读取版本 1 检查点时执行一次纯本地、幂等迁移：

- 每个任务赋值 `attempt: 1`；
- 每条已有结果赋值 `attempt: 1`；
- 补充空的 `manualResolution`；
- 保持原批次状态、任务状态、游标、设置和结果不变；
- 原子写入版本 2 后才向页面返回。

不支持或损坏的版本仍保留原始数据，并进入现有的不可自动恢复错误流程。

### 内容脚本阶段报告

内容脚本只报告受控枚举阶段，不上传任意 DOM 内容。阶段消息包含：

```js
{
  type: 'BATCH_TASK_PHASE',
  batchId,
  urlIndex,
  attempt,
  phase,
  occurredAt
}
```

后台拒绝：

- 外部发送者；
- 旧批次；
- 越界任务；
- 终态任务的后续阶段；
- 非枚举阶段。

## 稳定接口契约

### 批次分配

```js
{
  identityId: 'default-identity',
  promotionSiteId: 'default-promotion-site',
  identitySnapshot: {
    displayName: 'CloudHu',
    email: 'you@test.com'
  },
  promotionSiteSnapshot: {
    label: 'promo.test',
    url: 'https://promo.test/',

```

快照用于恢复和结果解释；运行时继续读取当前单一配置。后续多配置引擎可以改为按 ID 获取完整配置，而无需修改控制台组件输入。

### 控制台任务视图

```js
{
  taskId: 'batch-id:17',
  urlIndex: 17,
  attempt: 1,

  phase: null,
  elapsedMs: null,
  result: null,
  error: null,
  retryPolicy: 'safe',
  actions: ['details', 'retry', 'manual'],
  manualResolution: {
    status: 'idle',
    updatedAt: null
  }
}
```

### 错误

```js
{
  code: 'task_timeout',
  message: '处理超时，窗口已安全关闭',
  retryPolicy: 'safe',
  diagnostic: {
    phase: 'generating',
    elapsedMs: 61000
  }
}
```

诊断对象不得包含 API key、密码、完整邮箱或其他凭据。

## 数据流

### 创建

1. 用户选择当前默认身份和推广网站。
2. 预检模块解析 CSV 并返回预检结果。
3. 向导生成批次草稿和分配快照。
4. 用户确认开始。
5. 命令控制器发送 `BATCH_SESSION_START`。
6. 后台持久化完整检查点并申请保活。
7. 调度器领取最多 N 个任务并在控制台所在窗口创建后台 worker 标签页。

### 实时运行

1. worker 标签页和内容脚本发送受控阶段。
2. 后台持久化阶段并广播更新。
3. 控制台状态模块从检查点推导摘要、槽位和行。
4. 视图只渲染快照。
5. 终态确认持久化后关闭对应 worker 标签页并补位。

### 暂停和恢复

1. 用户确认安全暂停。
2. 命令控制器禁止补位并封存活动提交上下文。
3. 后台归一化活动任务并保存暂停检查点。
4. worker 标签页关闭，保活释放。
5. 用户继续时重新验证检查点、申请保活并补满槽位。

### 重试

1. 详情区读取结构化重试策略。
2. `safe` 直接确认；`confirm` 显示重复评论风险；`blocked` 不提供入口。
3. 后台验证策略并创建新的任务 attempt。
4. 任务回到排队，旧结果保留在尝试历史。

## 真实 Chrome 验收

使用真实 Chrome 加载当前 worktree 的未打包扩展。仅使用本地服务：

- 5 个不同路径的本地评论 fixture；
- 本地 OpenAI 兼容模型 stub；
- 本地 CSV；
- 不访问或提交到第三方评论网站。

验收步骤：

1. 配置本地模型 stub、默认身份和本地推广网站。
2. 导入包含 5 个本地 URL 的 CSV。
3. 确认预检结果和分配摘要。
4. 并发设置为 3 并开始。
5. 验证任意时刻最多 3 个自动 worker，槽位与真实 worker 标签页一致。
6. 验证前 3 个任务运行时，剩余 2 个显示排队。
7. 验证完成一个任务后立即补位。
8. 验证阶段、耗时、结果和错误实时更新。
9. 在运行中执行安全暂停，验证不再补位、worker 标签页安全关闭、检查点可恢复。
10. 继续后验证只处理安全的剩余任务。
11. 制造一个安全失败并验证直接重试。
12. 制造一个提交中断并验证只能默认进入人工处理。
13. 打开人工窗口，确认不会自动生成、填写或提交。
14. 刷新批次页，验证控制台从检查点完整恢复。
15. 验证停止确认和不可恢复结果。
16. 在 1440px、1024px 和约 640px 宽度检查布局、键盘焦点和完整任务信息。

验收记录包含：

- Chrome 版本和扩展版本；
- 测试日期；
- fixture 和 CSV 说明；
- 每一步结果；
- 截图路径；
- 确认没有第三方评论提交。

## 验收标准

- 批处理页不再是 700px 单列长表单。
- 固定操作栏在滚动时保持可见且不遮挡内容。
- 并发 3、5 个本地 URL 时，槽位和真实 worker 标签页始终一致，活动 worker 不超过 3。
- 表格覆盖排队、运行、成功、失败和需人工，而不是只显示终态。
- 每个活动任务显示受控阶段和实时耗时。
- 每个失败任务显示完整原因和正确重试策略。
- 人工窗口绝不接收自动化批次消息。
- 暂停可恢复；停止不可恢复；两者文案、样式和状态转换不同。
- 离线和关键检查点失败不会继续开窗或静默自动恢复。
- Chrome 重启或页面刷新后能从检查点完整恢复控制台。
- 统一导航清楚连接身份、推广网站、批次、历史和设置。
- 现有单一配置仍可运行，检查点包含 profile-ready 分配契约。
- 所有资源本地打包并兼容 Manifest V3 CSP。
- 完整自动化测试、语法检查和真实 Chrome 本地验收通过。

## 后续多身份集成接口

后续多身份任务只能替换以下边界：

- 将向导中的单一分配卡数据源替换为身份和推广网站列表；
- 让运行时按 `identityId` / `promotionSiteId` 读取不可变配置快照；
- 在批次级或任务级明确分配策略；
- 在结果和历史中保留实际使用的配置 ID。

本次实现不得：

- 在调度器中轮换身份；
- 给任务随机分配推广网站；
- 暗中从全局配置重新读取并覆盖批次快照；
- 为尚未定义的多身份策略增加占位逻辑分支。

这样可以保证本次 UI 契约稳定，同时不提前决定后续多身份调度策略。
