# 多窗口并发外链评论设计

## 背景

当前批量外链评论页面一次只允许一个活动标签页处理一个网站。核心限制是 `activeTabCount >= 1`，但仅提高这个上限仍不足以安全支持并发：

- 批量结果确认消息没有携带 `batchId`，延迟或其他批次的消息可能被当前页面误处理。
- 提交刷新恢复上下文使用单一 `batchSubmitCtx` 存储键，多个网站同时提交时会互相覆盖。
- 活动任务只按标签页跟踪，无法可靠关闭独立浏览器窗口。

本功能让一个批量任务同时在多个独立浏览器窗口中处理不同网站，并保证每个任务的状态、结果和恢复上下文相互隔离。

## 目标

- 一个批量任务可以同时处理多个网站。
- 每个活动网站使用一个独立普通浏览器窗口。
- 并发窗口数可设置为 1–10，默认值为 3，并记住用户上次的设置。
- 工作窗口尽量在后台创建，不反复抢占用户当前窗口的焦点。
- 任一网站结束、失败、被关闭或超时后，自动释放并发槽位并调度下一个网站。
- 保留现有的停止、恢复、进度统计、结果筛选和 CSV 导出能力。
- 并发任务之间不发生结果串写、重复计数或提交恢复上下文覆盖。

## 非目标

- 不支持同时运行多个独立 CSV 批次。
- 不把完整批量任务迁移到后台 service worker。
- 不保证批量管理页面关闭后任务继续运行。
- 不增加 AI 请求自动重试、全局速率限制或动态并发调节。
- 不改变现有评论表单识别、文案生成和提交策略。

## 用户体验

批量设置区域新增“并发窗口数”数字输入框：

- 最小值：1
- 最大值：10
- 默认值：3
- 输入越界或无效时恢复为最近一次有效值。
- 有效值保存到 `chrome.storage.sync`，下次打开批量页面时恢复。

用户开始批量任务后，系统创建最多 N 个独立浏览器窗口，每个窗口只处理一个目标网站。窗口以普通窗口形式创建，并尽量设置为非激活状态。Chrome 或操作系统若仍将新窗口显示到前台，扩展不通过额外聚焦操作反复抢占焦点。

网站产生终态结果后，对应窗口自动关闭，队列立即补充下一个网站。停止任务会关闭当前批次的全部工作窗口。恢复任务会跳过已经具有终态结果的 URL，并重新补满并发槽位。

## 架构

### 1. 并发队列调度器

从 `batch.js` 的单标签页调度逻辑中抽离一个可单元测试的调度核心。调度器负责：

- 保存并发上限、待处理索引和活动任务集合。
- 在任务开始、任务完成、窗口关闭、窗口创建失败、超时和恢复后执行补位。
- 保证活动任务数不超过配置的并发上限。
- 保证每个 URL 索引最多进入一次活动状态。
- 队列耗尽且所有 URL 均有终态结果时触发批次完成。

调度核心不直接依赖 DOM 或 Chrome API。`batch.js` 负责把调度决策映射为窗口创建、关闭、页面高亮和统计更新。

### 2. 活动窗口模型

每个活动任务至少包含：

```js
{
  batchId,
  urlIndex,
  url,
  tabId,
  windowId,
  startTime
}
```

使用以下索引支持消息、超时和关闭事件：

- `tabId -> activity`
- `urlIndex -> activity`
- `windowId -> activity`

窗口通过 `chrome.windows.create({ url, focused: false, type: 'normal' })` 创建。创建完成后从返回的窗口对象中取得首个标签页，登记 `windowId` 和 `tabId`，再等待内容脚本就绪并发送 `BATCH_HANDLE`。

终态清理优先使用 `chrome.windows.remove(windowId)`。如果窗口已经不存在，清理视为成功。关闭回调只负责释放资源和处理“无结果的用户手动关闭”，不得重复记录已有结果。

### 3. 任务身份与结果路由

任务唯一标识为：

```text
batchId + ":" + urlIndex
```

所有批量结果消息都必须保留 `batchId`：

- `BATCH_HANDLE`
- `BATCH_HANDLE_CONFIRM`
- `BATCH_CONFIRMED`
- `BATCH_REPORT_RESULT`

后台转发 `BATCH_CONFIRMED` 时包含原始 `batchId`。批量页面只在以下条件全部成立时处理消息：

- `message.batchId === currentBatchId`
- `urlIndex` 属于当前批次
- 该索引尚未拥有终态结果

延迟、重复、旧批次或不完整消息会被忽略，且不会关闭任何窗口。

### 4. 提交刷新恢复上下文

现有单一 `batchSubmitCtx` 会被并发提交覆盖，因此改为由后台按发送者标签页保存。

提交前，内容脚本向后台发送“保存提交上下文”消息。后台从 `sender.tab.id` 获取标签页 ID，并把上下文写入按标签页索引的本地存储映射。上下文包含：

```js
{
  tabId,
  batchId,
  urlIndex,
  url,
  result,
  aiContent,
  errorMessage,
  timestamp
}
```

页面刷新后，新内容脚本向后台请求当前发送者标签页的恢复上下文。后台只返回与该 `sender.tab.id` 对应且未过期的记录。内容脚本补发 `BATCH_HANDLE_CONFIRM` 后清除该标签页的上下文。

上下文保留现有 10 分钟有效期。批次完成、停止或活动窗口清理时，也会清理对应标签页的记录，避免残留状态影响之后的任务。

### 5. 批量设置

现有三个批量开关仍以批次级设置保存。一个批次内所有并发窗口共享同一组设置，因此它们不会发生语义冲突。

内容脚本的正式自动化执行仍只由 `BATCH_HANDLE` 触发。批次设置的读取保持兼容，但结果和提交恢复不再依赖单一全局执行上下文。

## 数据流

1. 用户上传 CSV，设置并发窗口数并开始任务。
2. 批量页面生成 `batchId`，初始化队列和统计状态。
3. 调度器领取最多 N 个 URL。
4. `batch.js` 为每个 URL 创建非聚焦普通窗口并登记 `windowId`、`tabId`。
5. 内容脚本就绪后收到带任务身份的 `BATCH_HANDLE`。
6. 内容脚本识别表单、生成文案、填写并尝试提交。
7. 提交前，内容脚本要求后台按发送者 `tabId` 保存刷新恢复上下文。
8. 内容脚本产生终态结果并发送带 `batchId` 的确认消息。
9. 后台持久化结果，再广播带 `batchId` 的 `BATCH_CONFIRMED`。
10. 批量页面校验任务身份、记录结果、关闭对应窗口并触发调度补位。
11. 所有 URL 均有终态结果后，批次进入完成状态并清理残留窗口和上下文。

## 错误处理

### 窗口创建失败

该 URL 记录为失败，错误信息为窗口创建错误。调度器释放预留槽位并继续领取下一个 URL，整批任务不停止。

### 内容脚本未就绪或消息发送失败

保留现有有限次数就绪检测。达到上限后记录失败、关闭窗口并补位，不等待通用任务超时。

### 用户手动关闭窗口

如果该 URL 尚无终态结果，记录为失败，错误信息为“用户手动关闭”。如果终态结果已经记录，关闭事件只清理活动记录。

### 超时

每个活动窗口独立按 `startTime` 计时。超过用户配置的超时时间后记录“处理超时”、关闭对应窗口并补位。一个窗口超时不会影响其他窗口。

### 重复或延迟结果

只有 `batchId` 与 `urlIndex` 均匹配且该 URL 未有终态结果时才接受。其余消息只记录诊断日志，不修改统计、不关闭窗口。

### 提交后刷新

后台按发送者 `tabId` 返回对应上下文。没有上下文、上下文过期或任务身份无效时，不重新生成文案，也不猜测任务归属。

### 停止与恢复

停止时先禁止调度补位，再将仍在处理且无结果的 URL 记为手动终止，清空计时器和活动映射，最后关闭本批次窗口。窗口关闭事件不得重复计数。

恢复时根据本地结果集合查找所有尚未处理的 URL，重建待处理队列，并补满当前并发上限。

### 现有终态

以下现有终态继续保留并释放并发槽位：

- `success`
- `skipped`
- `no_comment_box`
- `manual_required`
- `blocked_illegal`
- `fail`

## 测试策略

### 调度器单元测试

- 默认并发数为 3。
- 并发数限制为 1–10。
- 活动任务数永远不超过配置值。
- 初次启动会补满并发槽位。
- 任一任务完成后立即领取下一个。
- 不同完成顺序不会改变 URL 和结果的对应关系。
- 同一个 URL 索引不会被重复领取。
- 停止状态不再领取任务。
- 恢复只领取没有终态结果的 URL。
- 队列耗尽且全部处理完成时只触发一次完成。

### 消息路由单元测试

- 当前批次的合法确认被接受。
- 不同 `batchId` 的确认被忽略。
- 缺少任务身份的确认被忽略。
- 同一结果重复到达时只计数一次。
- 确认关闭的是匹配 `urlIndex` 的窗口。

### 提交上下文单元测试

- 两个标签页可同时保存不同上下文且互不覆盖。
- 每个标签页只能取回自己的上下文。
- 清除一个标签页上下文不影响另一个。
- 过期上下文不会返回。
- 没有有效 `sender.tab.id` 时拒绝保存或读取。

### 页面与集成验证

- 并发设置加载、保存及无效值恢复。
- `chrome.windows.create` 使用普通窗口和非聚焦参数。
- 成功、失败、无评论框、需人工处理、非法网站、超时和手动关闭都会释放槽位并补位。
- 停止会关闭全部工作窗口，恢复后重新补满并发数。
- 本地评论测试页面在多个并发窗口中能各自提交并正确归属结果。
- 运行完整 `npm test` 回归套件。

## 验收标准

- 配置并发数为 3、CSV 至少包含 5 个有效网站时，开始后最多同时存在 3 个工作窗口。
- 任一工作窗口结束后，在队列仍有任务时自动创建一个新工作窗口。
- 批次内任意时刻的活动工作窗口数不超过配置值。
- 每条结果与原 CSV URL 正确对应，不因完成顺序不同而串行。
- 两个窗口近乎同时提交并刷新时，均能恢复自己的任务上下文并正确确认。
- 停止、恢复、超时、手动关闭和批次完成不会产生重复统计或遗留工作窗口。
- 现有单窗口行为可通过把并发数设为 1 保持兼容。
